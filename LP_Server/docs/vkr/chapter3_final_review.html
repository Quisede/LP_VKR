Готовый вариант с источниками

Можно заменить текущие абзацы 3.1 на такой вариант или точечно добавить ссылки:

Для серверной части выбран C++, так как этот язык подходит для создания производительных прикладных сервисов и позволяет напрямую работать с системными библиотеками. В рамках проекта C++ используется как единый язык для backend-логики, моделей данных и взаимодействия с PostgreSQL.
Для клиентского интерфейса используется Qt, модуль Widgets. Он предоставляет набор средств для разработки настольных приложений: окна, формы, таблицы, кнопки, области прокрутки и механизмы компоновки элементов. Для выполнения HTTP-запросов на стороне клиента применяется QNetworkAccessManager из модуля Qt Network, что позволяет отправлять запросы к REST API и обрабатывать ответы сервера без ручной работы с низкоуровневыми сокетами [22].
В качестве серверной HTTP-библиотеки выбрана cpp-httplib. Это заголовочная C++-библиотека, позволяющая быстро организовать HTTP-сервер и зарегистрировать обработчики маршрутов. Такой вариант подходит для учебного проекта, поскольку не требует сложной инфраструктуры и позволяет сосредоточиться на логике обработки запросов [24].
Для обмена данными между клиентом и сервером используется формат JSON. Он удобен для передачи структурированных объектов, таких как пользователь, курс, тест, вопрос или результат прохождения. На стороне C++ обработка JSON выполняется с помощью библиотеки nlohmann::json, которая предоставляет удобный синтаксис сериализации и разбора JSON-объектов [21], [25].
В качестве системы управления базами данных выбрана PostgreSQL. Она поддерживает реляционную модель, ограничения целостности, внешние ключи и транзакционный подход к работе с данными. Для доступа к базе данных на стороне серверного приложения используется libpq — официальный C-интерфейс PostgreSQL [23].
Сборка проекта выполняется через CMake. Эта система позволяет описывать параметры сборки в едином виде, подключать внешние библиотеки и формировать проект для разных сред разработки [26]. Для развёртывания используется Docker Compose, с помощью которого backend-приложение и PostgreSQL запускаются как связанные сервисы в воспроизводимой среде [27].

После таблицы можно оставить не три абзаца, а один более плотный:

Структура приложения отражает последовательность обработки пользовательских действий. Пользователь выполняет операцию в клиентской части, после чего сетевой модуль формирует HTTP-запрос и передаёт его серверу в формате JSON. LoginWindow является входной формой приложения. Пользователь вводит логин и пароль, после чего форма обращается к ApiClient. Сетевой класс формирует POST-запрос к маршруту авторизации, а при успешном ответе сохраняет данные текущей сессии: токен, идентификатор пользователя и роль. Как улучшить абзац про ApiClient

ApiClient является промежуточным уровнем между графическим интерфейсом и серверным API. Он формирует URL, добавляет заголовок авторизации, подготавливает JSON-тело запроса и разбирает ответ сервера. Благодаря этому страницы интерфейса не работают с HTTP-запросами напрямую, а получают подготовленные модели данных.

Готовая замена для Docker-абзацев

При первом запуске контейнера базы данных используется init.sql, где создаётся схема и демонстрационный набор данных. Такой подход делает запуск проекта воспроизводимым и снижает количество ручных настроек на стороне пользователя или проверяющего.

Проблема с рисунками второй главы, которую видно при проверке

В текущем тексте есть путаница:

  • в тексте сказано, что ER-диаграмма представлена на рисунке 3, но подпись стоит «Рисунок 4 — ER-диаграмма»;
  • в тексте сказано, что последовательность тестирования представлена на рисунке 4, но подпись стоит «Рисунок 3 — Блок-схема прохождения тестирования...»;
  • значит, рисунки 3 и 4 нужно поменять местами в ссылках или в подписях.

Лучше сделать так:

  • Рисунок 1 — Общая структурная схема системы;
  • Рисунок 2 — Схема обработки пользовательского запроса в серверной части;
  • Рисунок 3 — Блок-схема прохождения тестирования и сохранения результата;
  • Рисунок 4 — ER-диаграмма базы данных LMS-платформы.

Тогда ссылки должны быть такими: перед блок-схемой тестирования писать «на рисунке 3», перед ER-диаграммой — «на рисунке 4».
